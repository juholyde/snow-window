# Keyboard and screen-reader audit, 2026-11-27 (task t29)

Scope: the Board timeline, overlap row, day details, Trips (suggest, answer) and the stay panel (vote, Booked it). Demo mode on `localhost:5191`, Chromium via `playwright-cli`, build at commit `23f6247`+.

## What was and was not run

- **Keyboard pass: done** with real key presses (Tab, Shift-Tab, Enter, Space, arrows, Escape). A few steps used `element.focus()` to skip the long tab runs (noted below) and the demo's second crew member was seeded in localStorage.
- **VoiceOver: NOT run.** It cannot be driven headless. The screen-reader pass is a read of Playwright's accessibility snapshot plus ARIA attributes in the DOM. Anything about how VoiceOver actually speaks it (live-region timing, emoji reading) is unverified and flagged "unverified".
- **axe-core 4.10.3** (from the local bun cache, served from localhost) found no violations on Board, Snow windows, account dialog; one `heading-order` (moderate) on Trips and Suggest (an `h3` follows no `h2`).

## Failures

Severity: blocker = a task cannot be done at all; major = done with great effort or silently losing place; minor = rough edge.

### Mark (Board)

1. **Blocker. You cannot mark your own days by keyboard or screen reader.** `AvailabilityTimeline.vue`, own row: 151 `div.cell` elements with only `@pointerdown`, no role, name, tabindex or key handler. They are absent from the accessibility tree (anonymous `generic`). Keyboard users reach "Options for Ana" and nothing in the row; the core action of the app is pointer only. Fix: make the own row a roving-tabindex grid (see item 3): focused day toggles on Space/Enter, Shift+Arrow extends a range, expose `aria-pressed` (or `aria-selected`) per day.
2. **Blocker. A day's marked state is never announced.** The own cells have no state; the other people's rows (`div.cell.free`) are likewise silent. The only per-day readout is the day-details strip (Enter on a header/overlap day), which lists who is free. Fix: name each cell `"{person}, {Sat 12 Dec}, free"` / `"not marked"` (or a row of `role=gridcell` with `aria-selected`).
3. **Major. 453 tab stops before the rest of the board.** The day header, overlap and forecast rows are each 151 `<button>`s, all in the tab order (Tab total on Board: 464). From "Jump to month" a keyboard user must press Tab ~450 times to reach "Options for Ana". There is no skip link. Fix: one tab stop per row (roving tabindex, arrow keys move, Home/End jump), or `role=grid` with a single stop; add "Skip to your row" while it is built.
4. **Major. Focus can be hidden under the sticky name column.** Shift-Tab along a row moved focus to cells at x=116..184 while the sticky column ends at x=201, and the container did not scroll. Fixed in this task (one line, `src/style.css` `.timeline { scroll-padding-left: calc(var(--name) + 20px) }`), verified: backward Tab now scrolls the cell into view.
5. **Minor. Overlap/forecast labels use ISO dates.** `aria-label="2026-12-13: 1 of 1 free"` while the header says "Sun 13 Dec". Use `formatLong(d)`.
6. **Minor. Focused day has no programmatic state.** The `focused` class marks the day whose details are open but there is no `aria-current` / `aria-pressed`.

### Overlap and day details

7. **Major (unverified in VoiceOver). Day details are not reliably announced.** `section.day-strip aria-live="polite"` is created together with its content (`v-if`), and live regions usually must exist before their text changes. Enter on a day keeps focus on the day (good) but a SR user may hear nothing. Fix: keep an always-present empty `role=status` and write the sentence into it.
8. **Minor.** "Options for Ana" opens the account dialog titled "You"; name and result differ.
9. **Minor.** `title` carries holiday/key-date info (hover only). Put it in the day button's name.

### Suggest a trip

10. **Major. Custom dates cannot be picked by keyboard.** In pick mode `focus(d)` is a no-op, so Enter on any day header/overlap/forecast button does nothing (453 dead stops) and the "New trip" row cells are `div`s (`tabindex -1`, name only in `title`). The only keyboard route is the "Best stretches" buttons, which needs two or more people free. Fix: in pick mode day buttons do the tap-first-then-last pick (Enter) with a status line "first day Sat 12 Dec, choose last".
11. **Minor.** "Best stretches" selection is a CSS class (`on`), no `aria-pressed`. The "Pick the dates / 3 nights" summary changes with no live region.
12. **Minor.** Trips view tablist (`Suggest | Answer`): `role=tab` with `aria-selected` but no arrow-key handling, no roving tabindex, no `aria-controls` and no `tabpanel`. Compare the top-level tabs in `App.vue`, which are correct (arrows work).
13. **Major. Focus is lost after submit.** "Suggest to the crew" leaves `document.activeElement` on `<body>` (the form unmounts as the view switches to Answer); the next Tab starts again at the top of the page. Same pattern on "Mark it on", "Add places" and "Booked it" (likely the `:disabled="busy"` flip on a focused button, or the node being removed). Fix: after each of these actions move focus to a stable target (the new trip card heading with `tabindex=-1`, the first stay) and keep `busy` from disabling the focused control (use `aria-disabled`).

### Answer

14. Works: "Going / Maybe / Can't" are in a `group "Ana's answer"` with `aria-pressed` and keep focus after Enter. **Minor:** tally avatars carry names only as `title` on emoji spans ("Free for all of it: ⛷️🏂"); give them visible or visually hidden text.

### Stay vote and Booked it

15. **Major. Vote and "Booked it" buttons have no usable names.** The vote button's name is `1 ⛷️` (heart icon hidden, count plus emoji; names only in `title`). "Booked it" and "Not booked" repeat for every stay with no stay name. A SR user hears "1, toggle button, pressed" ten times. Fix: `aria-label="Vote for Hotel Tuca, 1 vote: Ana"` and `aria-label="Mark Hotel Tuca as booked"`.
16. **Minor.** Booked state is only the text "Booked: Hotel Tuca" in the heading, with no live announcement; the vote change is announced only through `aria-pressed`.
17. Works: `aria-pressed` on Driving/No car; the stay link and remove buttons are named; the paste error has `role=alert`.

### Cross-cutting

18. **Major. Toasts and nudges are inserted already containing their text.** `div.toast role=status`, `.trip-nudge role=status` and `.celebrate role=status` are all created by `v-if`; several screen readers skip such insertions (unverified). Fix: one always-mounted `<div role=status class=visually-hidden>` that App.vue writes into.
19. **Major. Avatar radio group has no `name`.** `ProfileFields.vue` radios (30 of them) each take a Tab stop on the "Start a crew" form (28 stops to the name field) and Arrow keys do nothing. Fix: a shared `name`, unique per instance (the welcome form and the account dialog are both in the DOM, so a fixed name would merge the groups).
20. **Minor.** `heading-order` on Trips (axe).

### Works

Crew sheet and account dialog (native `dialog`): focus moves in, Escape closes and returns focus to the opener. Top-level tabs: arrows, `aria-selected`, roving tabindex. `PickMenu` listbox: Enter, arrows, Escape, focus back to the trigger. Focus rings are visible on every control tried (PickMenu options use a background highlight instead of a ring). No keyboard trap found.
